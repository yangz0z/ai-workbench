# MCP와의 차이

Notion에서 자료를 찾아 읽고 여러 페이지를 자유롭게 편집하려면 [공식 Notion MCP](https://developers.notion.com/guides/mcp/overview)가 잘 맞습니다. `markdown-notion`은 **로컬 문서를 정해진 데이터베이스에 올리고, 수정할 때마다 같은 항목에 반영하는 작업**에 맞춰져 있습니다.

| 비교 | 공식 Notion MCP | markdown-notion |
| --- | --- | --- |
| 주 용도 | Notion 검색·조회·여러 종류의 편집 | 로컬 Markdown의 데이터베이스 게시·갱신 |
| 연결 | OAuth로 공식 원격 MCP 서버 연결 | 로컬 스크립트에서 내부 연결 토큰으로 REST API 호출 |
| 반복 게시 규칙 | 사용하는 도구·에이전트의 작업 방식에 따라 구성 | 파일과 페이지 연결, 속성 매핑, 충돌 확인을 코드로 제공 |
| 접근 범위 설정 | 공식 서비스의 인증·권한 정책에 따름 | 내부 연결에 공유한 대상과 그 하위 항목으로 제한 |
| 준비·관리 | 공식 연결 절차 사용 | 로컬 실행 환경·토큰·매핑·게시 이력 관리 |

이 스킬은 대상별로 다른 내부 연결 토큰을 사용할 수 있습니다. 예를 들어 업무용 연결에는 업무 데이터베이스만, 개인용 연결에는 개인 데이터베이스만 공유합니다. 상위 페이지를 공유하면 하위 항목도 접근 범위에 들어갑니다. [Notion 내부 연결 권한](https://developers.notion.com/guides/get-started/internal-connections)

MCP는 연결 규약이므로 권한을 넓게 부여해야 하는 구조는 아닙니다. 직접 구현한 MCP 서버도 내부 연결 토큰과 같은 접근 제한을 사용할 수 있습니다. 스킬과 MCP를 함께 사용하는 것도 가능합니다.

## 단순해지는 부분과 남는 부분

이 스킬의 게시 경로는 다음과 같습니다.

```text
AI → 로컬 스크립트 → Notion API
```

별도 MCP 서버 연결·도구 등록·프로토콜 처리를 준비하지 않아도 됩니다. 다만 Notion 통신, 토큰 권한, API 제한과 오류 처리는 여전히 필요합니다. Python·uv 준비와 게시 이력 관리도 사용자가 맡습니다. 공식 MCP는 서버를 직접 운영하지 않아도 되는 장점이 있습니다.

**MCP보다 빠르거나 토큰을 덜 쓴다는 비교 측정은 없습니다.** 모델·도구 정의·출력 크기·호출 횟수·캐시 조건에 따라 달라지므로 성능 우위로 소개하지 않습니다.
