# 설계 도식 구성

## 무엇을 보여줄 것인가

| 질문 | 도식 | 반드시 읽혀야 하는 것 |
| --- | --- | --- |
| 어느 조건에서 다음 처리가 달라지는가 | 플로우차트 | 화살표 방향, 분기 조건, 종료·재시도 경로 |
| 누가 누구를 언제 호출하는가 | 시퀀스 | 참여자, 시간 순서, 호출·응답, 대기와 경계 |
| 어떤 데이터가 어떻게 연결되는가 | ERD | PK/FK, 관계 양끝, 1:N 또는 선택적 관계, 제약 |
| 무엇이 어디에서 실행되는가 | 아키텍처 | 프로세스·외부 시스템 경계, 의존·통신 방향 |
| 어떤 조건에서 데이터 상태가 바뀌는가 | 상태 전이 | 상태명, 사건·조건, 저장 결과, 종료 상태 |
| 시계의 시각과 실제 경과 시간이 어떻게 다른가 | 타임라인 | 시간대·날짜·UTC 후보·경과 시간 |
| 여러 실행자가 같은 자원을 처리하면 어떻게 되는가 | 동시 처리 시퀀스 | 경쟁 대상, 잠금·선점, 대기·재확인, 최종 결과 |

## 공통 구성

도식에 화면의 가장 넓은 영역을 배정. 도식에 이미 있는 라벨을 설명 카드로 반복하지 않음. 노드 선택 시 옆 패널에서 책임·필드·근거를 보완하고, 화면이 좁으면 패널을 아래로 배치.

확대·축소, 전체 맞춤, 필요 시 이동 기능 제공. 작은 화면에 전체를 억지로 축소하지 않음. 배율을 바꾸어도 선 끝·라벨·노드 클릭 영역이 맞아야 함. 초기 화면은 핵심 관계가 읽히는 범위로 맞춤.

정상 흐름과 오류 흐름은 선택으로 전환 가능하되 실제 분기 지점과 결과를 함께 표시. 시나리오를 바꾸면 단계·상태를 일관되게 초기화하고 되돌리기와 다시 시작 제공. DB 변경과 외부 발송을 같은 원자적 작업으로 오인시키지 않음.

## 연결선과 곡률

- 방향 전환에는 3차 베지어 곡선 등을 사용해 접선 방향이 자연스럽게 이어지도록 구성. 단순한 두 노드 연결에 불필요한 계단식 꺾임을 만들지 않음
- 시작·끝은 노드 경계의 연결점에 고정하고 제어점으로 출발·도착 방향과 곡률 조정. 화살표는 끝점의 진행 방향과 일치시키며 노드 안쪽을 침범하지 않음
- 곡선이 다른 노드를 지나면 먼저 연결 면·제어점·노드 간격을 조정. 우회가 필요하면 최소한의 곡선 구간으로 연결하고, 이어지는 구간의 접선 방향을 맞춤. 단순 충돌을 이유로 계단선으로 바로 되돌리지 않음
- 직교 경로는 사용자가 요청했거나 복잡한 관계에서 방향·분기 구분에 실질적으로 유리할 때만 선택. 시퀀스의 수평 호출·수직 생명선처럼 직선이 의미를 갖는 도식은 유지
- 라벨은 최종 곡선의 위치를 기준으로 배치하고 노드·다른 라벨·화살표와 겹치지 않게 조정. 변경 전 직교 경로의 중간 좌표를 그대로 재사용하지 않음
- 곡률만 바꾸어도 선택 경로 강조·클릭 영역·확대 시 연결점은 동일한 경로 데이터를 사용. 스크린샷에서 곡선의 매끄러움과 교차·가림을 함께 확인

## 플로우차트

처리 노드, 조건 노드, 시작·종료를 구분하고 모든 분기 화살표에 조건 표시. 실패가 전체 종료인지, 해당 건만 건너뛰는지, 재시도하는지 명시. 반복은 실제 루프 화살표로 표현.

예: `알림 조회 → 만료 조건? → EXPIRED` 또는 `SENT 조건부 UPDATE → 변경 행 1건? → 발송`. 텍스트를 가로로 나열하는 것만으로 분기 표현을 대체하지 않음.

## 시퀀스 다이어그램

참여자를 가로로, 시간을 세로로 배치. 호출 화살표와 응답 점선, 필요 시 활성 구간 표시. 트랜잭션 BEGIN/COMMIT/ROLLBACK은 실제 DB 작업 범위에 맞춰 주석·구간으로 표시하고 여러 요청이나 외부 발송까지 잘못 포함하지 않음.

잠금 대기는 무한 루프가 아닌 대기 구간으로 표시. 교착은 두 참여자의 보유 잠금과 서로 기다리는 요청을 보여줌. 정상/실패는 alt 구간이나 시나리오 전환으로 비교.

## ERD

- 테이블명 오른쪽에 전체 스키마 상세보기 아이콘을 배치. 테이블 본문 선택은 관계 강조, 아이콘 선택은 해당 테이블의 팝업 열기로 구분
- 팝업에는 실제 스키마 기준 전체 컬럼·타입·NULL 허용·기본값·PK/FK·유니크/CHECK 제약·인덱스를 표시하고, 가능하면 CREATE TABLE 원문도 제공
- 테이블명과 아이콘이 겹치지 않게 헤더 여백 확보. 아이콘에 테이블명을 포함한 접근성 이름과 툴팁 제공, Enter/Space로 열기·Escape로 닫기·닫은 뒤 포커스 복귀 검증
- 팝업을 닫은 뒤 주제를 이동하거나 테이블을 다시 선택해도 자동으로 재열리지 않도록 상태 정리. 보조 패널의 전체 스키마 버튼이 있으면 같은 팝업을 재사용

관계선은 실제 FK에서 참조 PK로 연결. 1:1, 1:N, 선택성을 검증하고 까마귀발 표기 또는 명시적인 양끝 라벨 사용. 선을 클릭하거나 선택 테이블의 연결을 강조해 경로를 따라갈 수 있게 함.

기본 ERD는 테이블명과 PK·FK 컬럼만 표시. 일반 컬럼·타입·제약·인덱스는 전체 스키마 상세보기 팝업에서 확인하도록 분리. 상태나 업무 식별자가 관계 설명에 꼭 필요한 경우에만 선택적으로 추가. 컬럼을 줄여도 모든 FK와 병렬 관계는 유지하고, 테이블 높이·연결선 끝점·카디널리티 위치를 실제 PK·FK 행에 맞춰 확인.

## 아키텍처

API와 작업자가 같은 프로세스인지, 별도 프로세스인지 실제 실행 설정으로 확인. 프로세스 분리가 DB 분리나 잠금 제거를 뜻하는 것처럼 그리지 않음. 직접 호출·DB 접근·메시지 전달을 구분하고 외부 시스템은 경계 밖에 배치. 파일·클래스 구조와 배포 구조를 혼합해야 할 때는 레벨을 명시.

## 상태 전이

노드는 실행 함수가 아닌 저장 상태. 화살표에 상태를 바꾸는 사건과 조건 표시. 취소·만료·실패도 실제 상태로 존재하는 경우에만 노드로 생성. 실패 로그만 남고 상태는 유지되면 자기 전이 또는 주석으로 표시.

서로 다른 엔터티의 상태도는 나란히 구별. 두 상태가 하나의 트랜잭션에서 함께 바뀌는지 별도 처리인지 표시하고, 표현을 간단하게 만들기 위해 동기화 보장을 만들어내지 않음.

## 시간대·시간 계산

시간 계산이 핵심 요구사항일 때 사용. 입력 현지 날짜·시각·IANA 시간대, 적용 가능한 UTC 후보, 선택된 시작, 실제 경과 시간으로 계산한 종료를 연결. 특정 날짜의 값은 프로젝트 계산 함수나 검증된 테스트로 확인하고 임의의 고정 시차를 사용하지 않음.

정상·없는 시각·두 번 있는 시각을 선택해 각각 후보 1개·0개·2개와 프로젝트의 선택 정책을 보여줄 수 있음. 현지 시계와 UTC 축은 구분하고, 경과 시간이 현지 시각 차이와 같지 않을 수 있음을 값으로 표현. 서머타임 정책이나 계산 정확도를 시각화 과정에서 변경하지 않음.

## 동시 처리

동일 대상을 만나는 실행자 A/B와 DB를 참여자로 배치. 발견 → 잠금/조건부 갱신 → 대기 또는 선점 실패 → 최신 상태 재확인 → 처리/건너뜀 순서를 실제 코드에 맞춰 표현.

잠금 해제 시점, 트랜잭션 경계, 영향받은 행 수와 유니크 제약의 역할을 구분. 한 가지 실행 순서는 `예시 순서`로 밝히고 스케줄링이 항상 같다고 주장하지 않음. 교착 설명은 잠금 소유와 대기 방향이 읽혀야 하며, 순서 통일 후에는 같은 자원에서 대기하는 흐름과 비교.

## 렌더링 선택

- 정적인 복잡한 도식은 Mermaid로 SVG 생성 가능. Mermaid 자체가 디자인은 아니므로 무채색 테마, 여백과 글꼴을 조정
- 단계·노드 선택이 핵심이면 SVG/React 기반으로 작성하거나 생성된 SVG에 안정적인 식별자를 연결
- React Flow 등 라이브러리는 실제로 이동·확대·노드 구성이 필요할 때만 도입
- 라이브러리 CDN 호출 없이 최종 HTML에 코드·SVG·스타일 포함
- SVG에 제목·설명 제공. 클릭 가능한 요소는 버튼 또는 적절한 역할·포커스·키보드 조작 제공

완료 전: 잘린 화살표, 노드 아래 숨은 관계선, 겹친 라벨, 역방향 호출, 잘못된 트랜잭션 범위, 색만으로 구분하는 상태를 확인.
