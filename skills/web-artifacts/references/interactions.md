# 경로와 단계 인터랙션

## 한 상태에서 도식과 설명 파생

노드와 연결선에는 안정적인 ID를 부여. 경로는 화면 좌표가 아니라 ID로 정의. 같은 시작·끝 사이에도 서로 다른 조건의 선이 있을 수 있으므로 시나리오가 지나는 연결선 ID를 명시하는 방식을 권장.

```ts
type Scenario = {
  id: string;
  label: string;
  nodeIds: string[];
  edgeIds: string[];
};
type Edge = {
  id: string;
  from: string;
  to: string;
  label?: string;
};
// 도메인과 무관한 예시 모델
const route: Scenario = {
  id: 'valid', label: '검증 통과',
  nodeIds: ['input', 'validate', 'save', 'done'],
  edgeIds: ['input-validate', 'validate-save', 'save-done'],
};
```

현재 시나리오·현재 단계·수동 선택을 구분하고 강조와 설명을 같은 상태에서 계산. 클릭한 노드가 선택 경로 안이면 해당 단계로 이동. 경로 밖의 노드를 열 수 있게 한다면 시나리오는 유지하고 `다른 분기 확인 중`처럼 구별하며, 다음 단계로 돌아오는 규칙을 일관되게 적용.

## 세 가지 시각적 역할

- 선택 경로: 노드·선·화살촉·분기 라벨을 기본 불투명도와 진한 무채색으로 표시
- 현재 단계: 해당 노드의 연노랑 배경, 단계 번호·제목을 함께 표시. 선·테두리는 기본 굵기 유지
- 다른 경로: 기본 시작값 opacity 0.22. 보조 경로가 존재함을 알아볼 수 있게 남기고 포커스·선택 시 읽기 가능한 대비 확보

경로 전체를 노랗게 채우지 않음. 현재 위치와 이동할 경로가 구분되어야 함. 색 외에도 시나리오 이름·분기 라벨·단계 번호로 의미 전달.

공유 선분은 비활성 선을 먼저 그리고 활성 선을 나중에 그려 활성 경로가 흐린 선 아래 숨지 않게 함. 분기 경로 자체가 출발 노드부터 연결되도록 정의하고 다른 경로의 일부 선분에 의존하지 않음. 노드·경로 레이어와 라벨이 서로 가리지 않는지도 확인.

## 조작부와 탐색

- 이전·다음·처음부터 버튼은 설명 위 일정한 위치. 단계 숫자는 고정 폭 또는 tabular-nums 사용
- 첫 단계에서 이전, 마지막 단계에서 다음 비활성화. 처음부터는 한 단계 이전과 구별되는 이름·접근성 라벨 제공
- 시나리오 변경 시 경로·단계·선택·설명이 함께 초기화
- 노드 클릭과 키보드 Enter/Space 선택을 같은 동작에 연결. 선택 강조와 키보드 포커스는 별개
- 도식 확대·축소·맞춤을 제공하되 모든 주제의 화면을 한 배율로 고정하지 않음
- 화면이 좁을 때 도식 글자를 계속 줄이지 않고 가로 탐색과 상세 패널 하단 배치 사용

## 확인할 동작

각 시나리오의 전체 경로와 끝 상태를 확인. 정상에서 실패로 바꿨을 때 이전 강조가 남지 않는지, 경로 밖 선택 후 진행이 일관적인지, 공유 선분·화살촉까지 강조되는지 확인. 짧은 설명과 긴 설명을 오가도 다음 버튼 좌표가 안정적인지 점검.

## 팝업 기본 동작

- 읽기 전용 상세보기 팝업은 닫기 버튼·Escape·바깥 배경 클릭으로 닫기
- 팝업 내부 클릭과 스크롤은 유지. 내부에서 시작한 텍스트 선택·드래그가 바깥에서 끝나도 닫지 않음
- 열 때 포커스를 팝업 안으로 이동하고, 열린 동안 키보드 포커스를 가둠. 닫으면 실행한 버튼이나 아이콘으로 복귀
- 접근 가능한 제목과 닫기 버튼 이름 제공. 작은 화면에서는 팝업 내부 스크롤을 허용하고 닫기 버튼은 항상 접근 가능하게 유지
- 바깥 클릭·내부 클릭·Escape·닫기 버튼·포커스 복귀를 헤드리스 브라우저에서 검증

## 아키텍처 노드 선택

- 노드를 선택하면 선택 노드와 직접 연결된 이웃 노드·연결선·선 라벨만 선명하게 유지하고, 나머지는 흐리게 표시
- 선택 노드만 연노랑 배경으로 현재 위치 강조. 이웃 노드와 연결선은 무채색·기본 선 굵기 유지
- 연결 관계는 명시적인 from/to ID로 판정. 좌표나 라벨 문자열로 추론하지 않고, 이웃끼리의 선까지 재귀적으로 강조하지 않음
- 흐린 노드도 클릭·키보드로 선택 가능하게 유지하고, 선택 시 강조 범위와 상세 설명을 함께 갱신
- 모든 노드에 대해 직접 이웃과 연결선만 강조되는지 검증. 필요하면 비활성 선을 먼저 그려 활성 선이 가려지지 않게 처리
