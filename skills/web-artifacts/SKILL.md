# 설계 설명 웹 아티팩트

설계와 명세를 한눈에 탐색하는 로컬 HTML 제작. React로 상태·선택·시나리오를 구성하고 단일 HTML로 묶는 방식을 기본으로 사용. React 앱을 단일 HTML로 묶는 제작 방식을 사용하며, 실행 시 외부 스킬 저장소에 의존하지 않음.

[assets/example.html](assets/example.html)은 저장소 구성과 제작 흐름을 설명하는 독립 실행 예제. 화면 구조와 조작을 참고하되, 예제의 노드·내용·화면 수를 다른 프로젝트에 그대로 복사하지 않음. HTML 자체가 수정용 원본이며 별도 빌드 불필요.

## 결과물의 중심

- 큰 도식이 본문, 짧은 설명은 보조 패널. 설명 카드를 나열하거나 테이블 이름을 박스에 넣는 것만으로 설계 시각화를 대신하지 않음
- 사용자가 궁금해하는 질문과 기존 자료·코드로 화면 구성. 이미 제공된 목적·내용을 다시 묻지 않음
- 주제별 탐색, 노드 선택, 단계 진행, 정상·실패 비교 중 설명에 필요한 조작만 제공. 화면 수나 레이아웃을 획일적으로 고정하지 않음
- 슬라이드는 요청할 때만 사용. 기본은 도식을 충분히 크게 보고 필요한 내용을 선택하는 웹 화면
- 현재 구현, 설명용 단순화, 미구현 제안을 구분. 임의로 만든 수치·관계·상태를 실제 구현으로 제시하지 않음

## 내용 선정

새 프로젝트의 설계를 구성하거나 내용을 보완할 때 [references/content.md](references/content.md)를 읽음. 코드·스키마·테스트에서 핵심 요구사항, 설계 이유, 정상·예외 흐름과 남은 한계를 추려 질문별 화면으로 구성. 이전 프로젝트의 테이블·상태·성능 수치를 복사하지 않음.

## 도식 선택과 인터랙션

[references/diagrams.md](references/diagrams.md)를 읽고 설명 목적에 맞는 도식을 선택.

- 플로우차트: 처리 순서, 조건 분기, 반복, 실패 경로
- 시퀀스 다이어그램: API·서비스·작업자·DB 간 호출, 응답, 잠금 대기, 트랜잭션 경계
- ERD: 테이블명·PK/FK·관계선·카디널리티를 기본 표시, 전체 컬럼·제약·인덱스는 상세보기 팝업
- 아키텍처: 실행 경계와 의존·통신 방향
- 상태 전이: 상태를 바꾸는 사건·조건과 저장 결과
- 타임라인: 현지 시각·UTC·경과 시간 또는 지연·만료 관계
- 동시 처리: 여러 실행자의 경쟁, 잠금 획득·대기, 중복 방지 결과

모든 유형을 억지로 넣지 않음. 예를 들어 작업자 설명은 흐름도와 트랜잭션 시퀀스가 적합하고, 스키마 설명은 ERD가 우선.

단계나 노드를 선택하면 **도식 안의 해당 요소와 상세 설명을 함께 갱신**. 설명 텍스트만 바뀌고 도식은 그대로인 인터랙션을 피함. 시나리오 선택 시 전체 경로의 노드·연결선·분기 라벨을 함께 강조하고, 다른 경로는 흐리게 표시. 현재 단계만 연노랑으로 구별. 구현 모델과 조작 규칙은 [references/interactions.md](references/interactions.md) 참조.

## 시각 언어

[assets/theme.css](assets/theme.css)를 기본 토큰으로 사용. 사용자 지정 디자인이 있으면 우선 적용.

- 배경, 본문, 제목, 메뉴, 아이콘, 테두리, 일반 버튼과 연결선은 무채색. 청회색을 무채색처럼 전체에 깔지 않음
- 색은 성공·진행·대기·오류 상태 배지, 선택된 필터 칩 등 **좁고 의미 있는 요소**에 사용하며, 도식 선택 강조에는 연노랑 배경을 허용. 제목·로고·사이드바·대형 패널·일반 실행 버튼은 기본 무채색
- 도식 선택은 연노랑 배경(#fff6cf)으로 강조하고 테두리·연결선은 기본 굵기를 유지. 선택 요소의 이름·상세 설명을 함께 표시하고 키보드 포커스 표시는 별도로 유지
- 방향이 꺾이는 연결선은 부드럽게 이어지는 베지어 곡선을 기본으로 사용. 직교 계단선의 모서리만 둥글게 깎는 방식으로 대체하지 않음. 일직선 관계는 직선을 유지하고, 선 끝·화살표는 실제 노드 경계에 연결. 우회·라벨 배치는 [references/diagrams.md](references/diagrams.md)의 연결선 기준 적용
- 제목은 `전체 아키텍처`, `상태 전이`, `동시 처리`처럼 내용 그대로 사용. `구성 요소의 관계를 따라갑니다` 같은 추상적 안내 문구로 제목을 대신하지 않음
- 도식 영역 확대 보기는 텍스트 버튼 대신 확대 아이콘, 복귀는 축소 아이콘 사용. 툴팁과 접근성 이름 제공
- 다음·이전·처음부터 조작부는 상세 패널 상단의 일정한 위치에 배치. 설명 길이·단계에 따라 버튼 위치가 흔들리지 않도록 구성
- 그라데이션, 장식적 네온, 과한 그림자, 대형 색상 면적, 모든 내용을 둥근 카드로 나누는 구성을 피함
- 한국어 가독성 우선. 기본 본문 16px 안팎, 주요 도식 라벨 14px 이상을 출발점으로 실제 공유 화면에서 확인. 긴 내용은 접거나 나누고 글씨를 계속 줄이지 않음
- 시스템 한글 글꼴을 기본으로 사용해 오프라인 파일 크기와 가독성 확보. 외부 글꼴이 필요하면 라이선스와 로컬 포함 여부 확인

## 제작과 전달

1. 사실 근거와 대표 정상·실패 흐름을 먼저 정리하고 도식 종류 결정
2. 컴포넌트 상태로 선택·진행을 관리. 작은 아티팩트는 순수 HTML/SVG/JS로도 구현 가능
3. [references/build.md](references/build.md)에 따라 별도 작업 공간에서 빌드하고 단일 HTML 생성. 백엔드 프로젝트의 의존성을 변경하지 않음
4. 헤드리스 브라우저로 오프라인 실행, 핵심 조작, 도식 넘침·겹침과 실제 가독성 확인. 색 외의 구분과 키보드 접근도 확인
5. 최종 HTML과 수정·재빌드 가능한 소스를 함께 보관. 빌드 환경은 별도 유지하되 임시 폴더에만 원본을 남기지 않음
6. 클릭 가능한 HTML 경로와 **파일 탐색기에서 산출물 폴더 → HTML 더블클릭** 등 구체적인 여는 방법, 주요 조작을 함께 안내

브라우저·앱 창은 직접 띄우지 않음. 배포·외부 업로드·전역 설치를 산출물 생성의 기본 단계로 추가하지 않음. 저장은 사용자 지정 위치 또는 대상 프로젝트의 산출물 폴더를 사용. 개인 문서 저장소나 다른 프로젝트에 자동으로 저장하지 않음.
